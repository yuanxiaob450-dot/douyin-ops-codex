# 参数校准表 · 21 个可校准参数

诊断引擎里的默认值是**行业基准与操作经验线**，不是平台承诺值，也不是你店铺的真实值。
凡是涉及钱的结论（保本 ROI、增量测算、退款损失、赔付风险），都取决于下面这些参数填得对不对。

**没校准就用默认值跑出来的报告，「方向」可用，「金额」不可用。** 报告里会明确标注这一点。

---

## 一、必校准（不填，钱的结论会失真）

| 参数 | 默认值 | 单位 | 怎么取到真实值 | 不校准的后果 |
|---|---|---|---|---|
| `gross_margin` 毛利率 | 0.40 | 小数 | （到手价 − 货成本 − 物流 − 包材）÷ 到手价。用自己 TOP10 商品的加权平均 | 保本 ROI 直接算错：默认 40% → 保本 2.5；实际 30% → 保本 3.33，差 33% |
| `platform_rate` 平台扣点 | 0.05 | 小数 | 抖店后台 → 资金 → 费率说明，按自己类目查。不同类目差异大 | 保本价偏低，误判「还有利润空间」 |
| `refund_rate_assumed` 退款率 | 0.08 | 小数 | 用售后退款明细实际算：退款金额 ÷ 有效订单实付金额 | 增量测算虚高，退款损失被低估 |
| `sign_rate` 签收率 | 0.97 | 小数 | 签收单量 ÷ 发货单量（物流后台或 ERP 导出） | 含退货的保本 ROI 偏乐观 |
| `logistics_cost` 单均物流成本 | 4.5 | 元 | 快递报价单的实际结算价（含面单费、偏远加收） | 成本卡缺项，净利算高 |
| `aftersale_rate` 售后损耗率 | 0.03 | 小数 | （退款金额 + 退货物流成本 + 破损重发成本）÷ 支付 GMV | 售后成本被漏算 |

## 二、强建议校准（影响优先级排序）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `ad_ratio_target` 推广费占比目标 | 0.15 | 按阶段定：新店爬坡期可到 0.25–0.35，稳定期压到 0.15 以内。报告用它判断「付费依赖度」 |
| `ctr_min` 商品卡点击率红线 | 0.03 | 用自己类目 TOP10 竞品的「猜你喜欢」渠道点击率中位数替代，不要用全站汇总值 |
| `conv_min` 支付转化率基线 | 0.02 | 用自己类目近 30 天中位数。货架场类目差异极大（生鲜 vs 美妆可差 5 倍） |
| `cart_rate_min` 加购率基线 | 0.06 | 同口径取自类目中位数 |
| `sell_through_min` 动销率基线 | 0.60 | 抖音 2026 更看动销质量：低于此线会触发店铺级治理 |
| `in_pool_rate_min` 商品卡入池率治理线 | 0.30 | 低于 10% 属「绝大多数是死链接」，引擎会直接判 P0 |
| `finish_rate_min` 短视频完播率基线 | 0.25 | 按时长分层：15 秒内可要求 35%，60 秒以上 15% 已属良好 |
| `service_thresholds.reply3min` 回复率门槛 | 0.85 | 以抖店后台「服务体验」页当前公示门槛为准 |
| `fulfillment_thresholds.ship24h` 24h 发货率门槛 | 0.90 | 以自己承诺的时效档位为准（承诺越短，门槛越高） |
| `fulfillment_thresholds.pickup_rate` 揽收及时率门槛 | 0.90 | 以抖店后台物流看板口径为准 |
| `min_aov_health` 客单价健康线 | 45 | 低于此线时，物流与包材成本占比会失控，需要提客单或改组合装 |

## 三、量纲类（填错会让判定整体偏移）

| 参数 | 默认值 | 说明 |
|---|---|---|
| `exp_score_floor` 体验分红线 | 60 | **百分制**。若你的数据源是 5 分制，引擎会先 ×20 换算再比较；两个口径不要混填 |
| `exp_score_target` 体验分达标线 | 80 | 同上。准入类资格一律以抖店后台当前公示为准 |
| `exp_score_legacy_floor` / `exp_score_legacy_target` | 3.8 / 4.6 | 仅当数据源为 5 分制且你希望按老口径看时才用 |
| `gmv_target_month` 月度 GMV 目标 | null | **不填就不做达成率结论**（引擎不会拿假设目标给你算达成率） |

## 四、怎么把参数传给引擎

**方式一：参数文件（推荐，可复用）**

```json
{
  "gross_margin": 0.35,
  "platform_rate": 0.05,
  "ad_ratio_target": 0.18,
  "aftersale_rate": 0.035,
  "sign_rate": 0.96,
  "logistics_cost": 4.2,
  "refund_rate_assumed": 0.09,
  "min_aov_health": 39,
  "ctr_min": 0.028,
  "cart_rate_min": 0.055,
  "conv_min": 0.022,
  "sell_through_min": 0.6,
  "in_pool_rate_min": 0.3,
  "finish_rate_min": 0.22,
  "reply3min_min": 0.85,
  "ship24h_min": 0.9,
  "pickup_rate_min": 0.9,
  "exp_score_floor": 60,
  "exp_score_target": 80,
  "gmv_target_month": 300000
}
```

```bash
node scripts/diag.mjs --in ./我的导出数据 --store "我的抖店" \
  --assumptions ./assumptions.json \
  --out-html ./out/诊断报告.html --out-json ./out/diag.json --out-md ./out/摘要.md
```

**方式二：命令行直传（适合脚本化、一次性试算）**

```bash
node scripts/diag.mjs --in ./数据 --assumptions-json '{"gross_margin":0.35,"refund_rate_assumed":0.09}' --out-html ./out/r.html
```

两种方式同时用时，`--assumptions-json` 覆盖参数文件里的同名键。

## 五、校准的三个纪律

1. **一次只改一个参数，改完对比结论差异。** 校准的目的是让结论对得上你的实际经营，而不是把报告调到「看起来好看」。
2. **毛利率与退款率必须来自账面，不能来自感觉。** 这两个参数一错，保本 ROI 与增量测算全错，且错得看不出来。
3. **阈值类参数（红线/基线）用类目中位数，不要用自己店铺的历史均值。** 用自己均值会把「一直做得差」当成「达标」。

> 校准完成后，建议把 `assumptions.json` 与导出数据一起归档，下次重跑只换数据不换参数——这样不同周期的报告才可比。
